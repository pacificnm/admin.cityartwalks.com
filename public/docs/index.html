📋 Project Organization Rules

  • No exceptions - all other documentation goes in /project-docs/

  • All site and developer documentation must be maintained in the cityartwalks.com.wiki/
  • Module documentation is REQUIRED - every module, component, utility, and API endpoint must have corresponding wiki documentation
  • No undocumented code - all new modules must include wiki documentation before merging
  • Documentation standards - follow existing wiki patterns and templates for consistency

  • All project scripts (analysis tools, utilities, generators) must be placed in /project-scripts/
  • No scripts should be placed in the root directory
  • Includes: .js analysis scripts, .sh utilities, custom build tools, etc.

✅ Compliance

Before starting any project change:

  1. Check that all existing docs are in /project-docs/
  2. Check that all scripts are in /project-scripts/
  3. Place any new docs or scripts in the appropriate directory
  4. Ensure all modules have wiki documentation - check cityartwalks.com.wiki/ for existing docs
  5. Create wiki documentation for new modules - use existing templates and patterns
  6. Run relevant test groups - validate functionality with npm run cypress:groups:<group>
  7. Achieve 100% test pass rate - all tests must pass before proceeding
  8. Update references to moved files in other documentation

Violation of these rules will require cleanup before proceeding with changes.

� Project Overview

City Art Walks is a Next.js application that helps users discover public art installations, murals, and sculptures through interactive maps and curated walking paths. Built with modern web technologies and following enterprise-grade patterns.

🛠 Technology Stack

  • Frontend: Next.js 14, React 18, Material-UI
  • Backend: Node.js, Prisma ORM, PostgreSQL
  • Authentication: Auth0
  • Analytics: Custom throttled tracking system
  • Maps: Google Maps API
  • Deployment: Vercel

🚀 Getting Started

  1. Clone the repository

    git clone https://github.com/pacificnm/cityartwalks.com.git
cd cityartwalks.com

  2. Install dependencies

    npm install

  3. Set up environment variables

    cp .env.example .env.local
# Edit .env.local with your configuration

  4. Run the development server

    npm run dev

  5. Open your browser Navigate to http://localhost:3000

🧪 Testing & Validation

Testing is REQUIRED to validate all module functionality before deployment.

Test Groups

The project uses Cypress for comprehensive API testing organized into logical groups:

Available Test Groups

  • npm run cypress:groups:comm - Communication modules (email, chat, notification)
  • npm run cypress:groups:user - User management and preferences
  • npm run cypress:groups:content - Content modules (art pieces, artists, images)
  • npm run cypress:groups:location - Location services (cities, countries)
  • npm run cypress:groups:business - Business logic (posts, products)
  • npm run cypress:groups:analytics - Analytics and tracking
  • npm run cypress:groups:validation - Data validation and testing utilities

Test Group Requirements

  • 100% pass rate required - All tests in a group must pass before module changes are approved
  • Run relevant groups - Test the groups that contain modules you've modified
  • Document results - Record test results in /project-docs/ for tracking
  • Fix failures immediately - Address any test failures before proceeding

Running Tests

# Run all test groups and generate summary
npm run cypress:groups:all

# Run specific group
npm run cypress:groups:comm

# Run individual Cypress tests
npm run cypress:open

Test Scripts

  • /project-scripts/run-cypress-groups.js - Automated group test runner
  • /cypress/ - Individual test files organized by module
  • Test results - Documented in /project-docs/CYPRESS-TEST-GROUPS-RESULTS-SUMMARY.md

  • ✅ Role-based access testing - No more 403 errors with client credentials
  • ✅ Enhanced error handling - Prisma/model errors exposed in debug mode
  • ✅ Automatic token management - Expiry tracking and refresh
